# docs

What suveryn-core's documentation holds, one line each.

- [architecture.md](architecture.md): what exists, data flow, where confidential data lives, invariants, decisions with evidence, known limitations, the review checklist.
- [harness.md](harness.md): what happens around the model, from the passages to the checks.
- [translations.md](translations.md): where every piece of text lives, the copy rules, adding a language.
- [content-security-policy.md](content-security-policy.md): how the browser code stays within the appliance's Content-Security-Policy.
- [design/chat-ui.md](design/chat-ui.md): the chat interface, screen by screen.
- [design/admin.md](design/admin.md): *Administration*, page by page.
- [design/avatars.md](design/avatars.md): a person's picture, or their initials.
- [design/cases.md](design/cases.md): cases, their members, rights, closing and deletion.
- [design/playbooks.md](design/playbooks.md): playbooks as a routine in a case: how a run works, what it records, deed intake. The manifest format is in the public guide, [Writing a playbook](https://github.com/suveryn/suveryn-docs/blob/main/playbooks/writing-a-playbook.md).
- [design/platform.md](design/platform.md): capabilities, profession packs, playbooks and connectors, and the order of work.
- [design/templates.md](design/templates.md): from confirmed facts to a draft deed (proposed).
- [design/answer-checks.md](design/answer-checks.md): how an answer is checked by rule, the words each language reads, and a proposal for meaning.
- [design/messages.md](design/messages.md): the codes the server says when something goes wrong or needs checking.
- [design/names.md](design/names.md): how an operation and a code are named, and what "released" means.
- [spikes/react-aria/README.md](spikes/react-aria/README.md): the spike that chose React Aria under the strict CSP.
