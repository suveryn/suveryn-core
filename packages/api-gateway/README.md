# api-gateway

The HTTP surface (FastAPI). It contains no business logic: it validates requests and calls the `harness` ([docs/harness.md](../../docs/harness.md)) and, for documents, `rag`.

Document endpoints work when `suveryn-rag` is installed (`uv sync --all-packages`, GPU machine) and `SUVERYN_DATABASE_URL` is set. Otherwise they answer 503, and `/health` reports `documents.status: unavailable`. Saved conversations need only `SUVERYN_DATABASE_URL` (they don't need `suveryn-rag`); without it they answer 503 and `/health` reports `history.status: unavailable`.

| Endpoint | Behaviour |
|---|---|
| `GET /health` | 200 when llama-server is ready (reports the served model); 503 when it is loading, failing or unreachable. Also reports `documents`, `auth`, `history` and `usage` status. Public, so states only: no addresses or error texts (the server log has them) |
| `GET /auth/login` | Starts signing in: redirects to the Keycloak login page (authorization code + PKCE). Public |
| `GET /auth/callback` | Keycloak sends the browser back here; the gateway exchanges the code, validates the tokens and sets the session cookie |
| `GET /auth/me` | The signed-in user (`username`, `name`, `admin`, and the appliance's case settings `office_wide` and `cases_keep`), or 401 |
| `POST /auth/logout` | Ends the session; returns `logout_url`, Keycloak's end-session URL, which the UI opens to end the Keycloak session too |
| `POST /v1/chat` | `stream: false` returns a `ChatResponse` (JSON); 502 if the backend fails; 422 if the request is invalid (e.g. the last message isn't the user's, or more than 200 messages) |
| `POST /v1/chat` with `stream: true` | Server-Sent Events: `status` events before the first word (`{step, passages, complete, model}`; `step` is `searching`, `loading_model`, `reading` or `writing`, and only real pipeline steps are reported), for a grounded answer one `sources` event (`{citations}`, the passages it is written from, the same list `done` carries), then `delta` events (`{text}`), then exactly one `done` (a full `ChatResponse`) or `error` (`{message}`). After `error`, discard the partial text. **Closing the connection stops the answer** (*Stop*, docs/design/sidebar.md §5): the gateway watches the connection from the start, also before the first word, and closes its own to llama-server, which stops generating; the tokens used so far are still recorded. An unexpected server error gives a generic message, never the exception text |
| `POST /v1/chat` with `document_ids` | A grounded answer: `[n]` markers in `answer`, `citations[n-1]` holds the passage with its page. 503 if document search is unavailable. With `case_id`, the documents must be uploaded documents of that case (never sūveryn's own output), and the caller must be able to read it; without, the caller's own |
| `POST /v1/documents[?case=]` | Upload a PDF, Word (.docx), Excel (.xlsx), Markdown (.md) or CSV file (multipart `file`, ≤100 MB) into the caller's personal space, or into a case (a contributor's right; 404 for a case the caller may not see, 403 for one they may only read or that is closed). Returns a job at once (202); 415 for another file type, or a file whose first bytes don't fit its extension; 413 if too large (checked from `Content-Length` before the body is read); 411 without `Content-Length`; 429 when 20 of the caller's documents (or 200 in all) are waiting. A PDF over `SUVERYN_MAX_PAGES` pages (2,000) fails its job |
| `GET /v1/documents/jobs/{id}` | Job status: `queued`, `processing`, `ready`, `needs_review`, `failed` or `cancelled`, plus `document_id` when stored. While processing, `progress`: `{step, done, total}` (`ocr` page by page, then `layout`, then `store`; `read` for Word, Excel, Markdown and CSV). When failed, `error` (English) and `error_code` (`password`, `damaged`, `too_many_pages`, `too_large`, `no_text`, `unsupported`, `timeout`, `unreadable`) with `error_detail` (`pages`, `max`, `minutes`) for the interface to say why in its language |
| `DELETE /v1/documents/jobs/{id}` | Cancel one of the caller's uploads (204): one still waiting is never read; one being read is stopped, its reader process with it, before it is stored; one already being stored finishes. 409 once it is read (delete the document instead), 404 if unknown. Noted in the case's access log (`upload_cancelled`) |
| `GET /v1/documents[?case=]` | Stored documents (newest first) in the caller's personal space, or in a case, and the caller's uploads there still in progress or failed (finished jobs are forgotten after an hour). Each has its `origin` (`uploaded`, `generated`, `playbook`) and `uploaded_by`. 503 if the database can't be reached after one reconnect |
| `GET /v1/documents/all` | Every document the caller may see, newest first, each with its `case_id` (null: their personal space): the sidebar's *Documents* ([docs/design/sidebar.md](../../docs/design/sidebar.md)). No jobs: those are per place |
| `GET /v1/documents/{id}/conversations` | The caller's saved conversations that cite or attach the document (asked before deleting it) |
| `DELETE /v1/documents/{id}?conversations=clean\|delete[&case=]` | Delete a document and its passages (204; 404 if unknown or outside the personal space or the case named; in a case, the manager's right, or the uploader's own upload that carries sūveryn's export mark and that nobody confirmed yet). Saved conversations citing it lose its passages, headings and file name (`clean`, the default), or are deleted too (`delete`) |
| `POST /v1/cases/{id}/documents` | Save an answer to its case (docs/design/sidebar.md §5): `{filename (.docx), text, content, conversation_id, message_id}`; a contributor's right in an open case (403 otherwise, 404 for a case the caller may not see). A document with origin `answer`, never a source; `content` is what rebuilds its Word file in the browser (≤ 2 MB). 201 `{id, filename, created: true}`; the same `message_id` again: 200 with the document already saved. Logged as `answer_saved`. The person who saved it may delete it as a contributor (*Undo*) |
| `GET /v1/documents/{id}/content[?case=]` | What rebuilds a document sūveryn made (a saved answer), for whoever may read it; 404 for an upload or a document elsewhere |
| `POST /v1/documents/{id}/source[?case=]` | Use an upload that carries sūveryn's own export mark as a source anyway (docs/design/sidebar.md §6): the uploader's right in their personal space, a contributor's in a case; logged as `source_confirmed`. 404 if the document isn't there or nothing was noticed. Documents in the lists carry `source` (the model may cite it) and `provenance` |
| `GET /v1/conversations[?case=]` | The caller's saved conversations in their personal space, or in a case their own and the ones its members shared (stage 4), most recently changed first: `id`, `title`, `created_at`, `updated_at`, `case_id`, `owner`, `shared` (no content) |
| `GET /v1/conversations?all=true` | Everything the Conversations overview lists ([docs/design/sidebar.md](../../docs/design/sidebar.md) §4): the caller's own saved conversations everywhere they may still look (their personal space and every case they may read), and the ones colleagues shared with a case the caller may read, most recently changed first, up to 500. Each with `messages` (how many turns) and, for a colleague's, `owner_name` (their name as the case knows it) |
| `GET /v1/conversations/{id}` | One saved conversation with its `turns` (404 if unknown, expired or another user's, unless shared with a case the caller may read) |
| `PUT /v1/conversations/{id}` | Save a whole conversation (`{title, turns, case_id?}`) under an id the client chose (a UUID), replacing an earlier save (204). A new conversation goes into `case_id` (or the personal space) and stays there. 413 above 2 MB; 404 if the id is another user's or the case can't be seen |
| `GET /v1/cases[?closed=true]` | The cases the caller may see (suveryn-tracker#10): open ones first, most recently active first, each with `my_role` (`reader`, `contributor`, `manager`, or null for an administrator who only sees it exists). Closed cases only with `closed=true` |
| `POST /v1/cases` | Open a case: `{reference, name, type, subject?, access?}` (201). The reference is the office's own file number, unique on the appliance (409 if taken); never a client's name. The caller becomes its manager |
| `GET /v1/cases/{id}` | One case (404 if unknown or not visible to the caller; 403 for an administrator who isn't a member) |
| `PATCH /v1/cases/{id}` | Change reference, name, type, subject or access (`default`, `restricted`): the manager's right (403 otherwise, or when the case is closed) |
| `DELETE /v1/cases/{id}` | Delete a case with its documents and conversations (204): the manager's right. For a case opened by mistake; closing (stage 3 of the design) is the normal end |
| `GET /v1/cases/{id}/members` | The case's members (id, username, name as when added, role, who added them, when), the manager first; for anyone who may read the case |
| `PUT /v1/cases/{id}/members/{user}` | Add a colleague as `reader` or `contributor`, or change a member's role (the manager only; 403 otherwise or when closed). The colleague must be an enabled account in the office's directory (404 if not). 422 for `manager`: hand the case over instead |
| `DELETE /v1/cases/{id}/members/{user}` | Take a member out (the manager only; 422 for the manager themselves) |
| `POST /v1/cases/{id}/handover` | `{user}` becomes the manager, added as a member if needed; the previous manager stays as a contributor. The manager may, and an administrator (403 otherwise) |
| `POST /v1/cases/{id}/close` | Close an open case (stage 3): read-only from then on, `keep_until` set one keep period ahead (null with `SUVERYN_CASES_KEEP=manual`). The manager only (403; 409 if already closed) |
| `POST /v1/cases/{id}/reopen` | Reopen a closed case: open again, no deletion planned. The manager only (409 if open) |
| `POST /v1/cases/{id}/keep` | `{keep?: bool, extend?: bool}` on a closed case: `keep: true` marks it kept (never deleted by the period), `keep: false` lets the period run again from now, `extend: true` adds one period to its deletion date. The manager, or an administrator (403 otherwise; 409 if open; 422 with neither) |
| `GET /v1/cases/due` | Closed cases due for deletion within 30 days (or overdue) and not marked kept, soonest first: every one for an administrator, the ones they manage for anyone else |
| `PUT /v1/cases/{id}/pin` | `{pinned: bool}`: pin the case in the caller's own sidebar, or unpin it (anyone who may read the case; per user; not in the access log). `GET /v1/cases` and `GET /v1/cases/{id}` carry `pinned` for the caller |
| `GET /v1/cases/overview` | Every case the caller may see, open and closed, as the Cases overview shows them (docs/design/sidebar.md §4): each `Case` with its `members` (the manager first, with their pictures' ETags), and `last_activity_at` and `last_activity_by` (a name) from the access log. An administrator who isn't a member gets no members: only that the case exists |
| `POST /v1/conversations/{id}/share` | `{shared: bool}` (stage 4): share one of the caller's conversations with its case, or stop; its owner only, in an open case they may contribute to (403 otherwise; 404 for a personal conversation). A shared conversation is listed and readable for everyone who may read the case, read-only for them (saving, sharing or deleting it answers 404 for anyone but its owner) |
| `GET /v1/admin/cases` | Administrators only (403): every case, open ones first, with `manager_username`, `manager_name` and `members` (a count); nothing from inside a case |
| `GET`/`PUT /v1/admin/cases/settings` | Administrators only: the office's case settings as they apply now, `default_access` (`office`, `members`) and `keep` (`6m`, `1y`, `5y`, `manual`), with when and by whom they were last changed here (`updated_at` null: as provisioned). `PUT` takes either or both (422 with neither); effective at once for new cases and cases closed from now on |
| `GET /v1/cases/{id}/events` | The access log, newest first: `user`, `at`, `action` (`created`, `opened`, `uploaded`, `asked`, `document_deleted`, `changed`, `access_changed`, `member_added`, `role_changed`, `member_removed`, `handed_over`, `closed`, `reopened`, `keep_changed`, `conversation_shared`, `conversation_unshared`) and a `detail` of ids and roles, never text. The manager and the administrators (403 otherwise); kept 180 days |
| `GET /v1/cases/{id}/playbooks` | The playbooks that fit the case's type (suveryn-tracker#51, [docs/design/playbooks.md](../../docs/design/playbooks.md)): `id` (`playbook/be-notary/deed-intake`), `slug`, `pack`, `version`, `covered` (certified and in the appliance's manifest; false: it runs, with a warning to everyone, never blocked) |
| `GET /v1/admin/playbooks`, `PUT /v1/admin/playbooks/{slug}` | Administrators only (403): every installed playbook with its `case_types` and `active`, and `{active: bool}` to switch one off or on for the whole office ([docs/design/sidebar.md](../../docs/design/sidebar.md), 15). Off, it leaves `GET /v1/cases/{id}/playbooks` and starting a run answers 404; runs already made stay |
| `POST /v1/cases/{id}/playbooks/{slug}/runs` | Start a run (a contributor, open case): reads the case's uploaded documents (`document_ids`, or all) with one grounded model call; answers 202 with the run in status `reading`; poll it |
| `GET /v1/cases/{id}/playbooks/runs`, `…/runs/{run}` | The case's runs (a reader's right), and one run with its `facts`: per fact `value` as read, `citations` (the passages, kept with the run), `issues` (the chat's checks: a figure, date or name not in the cited passage, or in no passage), `found`, `confirmed`; `status` `reading`, `checkpoint`, `confirmed` or `failed` (`error` by kind); `playbook_id` and `playbook_version` on every run; `out_of_date` once a document it read is deleted |
| `PUT /v1/cases/{id}/playbooks/runs/{run}/facts` | The checkpoint (a contributor): `{facts: [{id, confirmed}], language}`; 409 unless the run is at its checkpoint. The summary is then stored in the case as a document with origin `playbook` (`result_document_id`), never a source for answers; it carries the run's own `playbook_version`. Starting a run shares the chat rate limit; a run `reading` when the gateway stopped, or for over thirty minutes, is failed as `interrupted` |
| `GET /v1/users/{sub}/avatar`, `PUT`/`DELETE /v1/me/avatar`, `DELETE /v1/users/{sub}/avatar` | Avatars ([docs/design/avatars.md](../../docs/design/avatars.md)): a colleague's picture (WebP, `ETag`, 304 on `If-None-Match`; 404 without one, the UI shows initials); set your own (the image as the body, ≤ 2 MB, PNG/JPEG/WebP, re-encoded on the server; 413, 415) or remove it; administrators remove anyone's. `/auth/me`, `/v1/users` and a case's members carry `avatar` (the ETag) and `admin` (the badge) |
| `GET /v1/users?q=` | The office's accounts (id, username, name) whose username, name or email contains `q`, from Keycloak through the `suveryn-directory` client; 503 without it |
| `DELETE /v1/conversations/{id}` | Delete one saved conversation (204; 404 if unknown) |
| `DELETE /v1/conversations` | Delete all of the caller's saved conversations (`{"deleted": n}`); the UI's *Delete history* when signing out |
| `GET /v1/usage?start=&end=` | The caller's own token usage (ISO 8601 times with a time zone; default the last 24 hours, `end` defaults to the server's now): `totals`, a zero-filled `series` (5-minute, hourly, daily or weekly buckets starting at local time), `by_kind`. Never a colleague's |
| `GET /v1/admin/usage?start=&end=` | Administrators only (403 otherwise): the same for the whole office, plus `per_user` (username, name, totals, notional cost; most tokens first), the `rates` and the office's notional `cost` |
| `GET`/`PUT /v1/admin/usage/rates` | Administrators only: the notional-cost rates (`input_per_million`, `output_per_million`, `currency`); `PUT` records who changed them |
| `GET /openapi.json` | The API description, served locally |

Saved conversations ([`conversations.py`](src/suveryn_api_gateway/conversations.py), suveryn-tracker#5) are private in the same way, keyed by the Keycloak user id. They are kept until the user deletes them. The office can choose a keep period, the same way as for closed cases: `SUVERYN_CONVERSATIONS_KEEP` as provisioned (`6m`, `1y`, `5y` or `manual`, the default: nothing is chosen for the office; the appliance's `--conversations-keep`), changed by an administrator in the dashboard's case settings (`conversations_keep`): older conversations, counted from their last change and in cases too, are deleted when the gateway starts, whenever someone lists theirs, and by the hourly sweep. What deleting guarantees is the [data lifecycle](https://github.com/suveryn/suveryn-docs/blob/main/administration/data-lifecycle.md). A saved answer quotes the passages it cites; deleting a document takes them out of every saved conversation, or deletes those conversations (suveryn-tracker#12). The answer text itself stays.

**Cases** ([`cases.py`](src/suveryn_api_gateway/cases.py), suveryn-tracker#10; design in [docs/design/cases.md](../../docs/design/cases.md)). A case is the file a confidential profession works on. Every document and conversation is in one scope: a case (`case_id`), or the uploader's **personal space** (no case; the user's own, as before cases existed; documents stored before cases land there, per owner). A request names its case with `?case=` (documents, conversations) or `case_id` (chat); the gateway decides once per request (`scope_of` in `routes/common.py`) whether the caller may `read`, `contribute` or `manage` there with the one authorisation function `may(user, case, role, action, office_wide)`, and the rag store then only looks inside that scope. A case the caller may not see is 404, like a missing one. Only uploaded documents are sources for answers; a document sūveryn generated is listed but never cited.

**Members and roles** (stage 2). A case has exactly one manager (its creator, until handed over) and any number of readers (open the case, read its documents) and contributors (also upload and ask). The manager adds colleagues from the office's directory, changes roles, removes members, hands the case over, and restricts or opens it. The default access is per appliance: `SUVERYN_CASES_DEFAULT_ACCESS=members` (the default: a case is its members' only) or `office` (everyone signed in reads an unrestricted case). An administrator (realm role `suveryn-admin`) sees every case exists and who manages it, hands one over (decision 6: an account can't go while it manages a case) and reads its access log, but not what is in it unless a member. **The access log** (`case_events`) records who did what in a case (opened, uploaded, asked, deleted a document, changed its details or access, members and handovers) with ids and roles only, never text; its manager and the administrators read it; lines are deleted after 180 days, as the sign-in events. **The directory** ([`directory.py`](src/suveryn_api_gateway/directory.py)) reads Keycloak's accounts through a client of its own, `suveryn-directory` (see [keycloak/README.md](keycloak/README.md)): a service account whose only right is `view-users`; the chat client keeps no service account. Without a database the case endpoints answer 503 and `/health` reports `cases.status: unavailable`; without the directory client's secret, `/v1/users` and adding members answer 503 and `/health` reports `directory.status: unavailable`.

**Token usage** ([`usage.py`](src/suveryn_api_gateway/usage.py), suveryn-tracker#7). The harness reports every model call's token counts (`suveryn_harness.usage`), and the gateway stores them, one raw row per call, in `token_usage`: user id, time, kind (`chat`, `summary`, `playbook-step`), model and llama-server's own prompt/completion counts. **No text.** As decided in the development context (§5.3), there is one table with raw rows kept indefinitely and no rollups: a few hundred calls a day per office stay quick to sum. Usernames for the administrator's table live in `usage_users`, updated when someone asks a question. Reports group by local time (`SUVERYN_TIMEZONE`, default `Europe/Brussels`). The notional cost uses an administrator-editable rate per million input and output tokens (`usage_rates`), defaulting to $3 and $15 (the published price of a comparable cloud model); hardware and power are not modelled. Usage is informational: nothing is ever limited because of it. Without a database, answers work and the usage endpoints answer 503.

**Closing, the keep period and deletion** (stage 3, decisions 10 and 11). Its manager closes a case: it stays readable for everyone who could read it (documents, conversations, export), nothing can be added to it, and its manager can reopen it while it is kept. How long a closed case is kept is the office's choice per appliance, `SUVERYN_CASES_KEEP`: `6m`, `1y`, `5y`, or `manual` (the default: nothing is chosen for the office, a closed case stays until someone deletes it). Closing sets `keep_until` one period ahead; from 30 days before that date the case is listed at `/v1/cases/due` for its manager and the administrators (the chat UI warns them in the sidebar and on the case), who can **extend** it by one more period, **reopen** it, or mark it **keep** (`keep: true`: the date stays but the case is never deleted by it; `keep: false` starts a period from now). An hourly sweep in the gateway (`sweep_due_cases`, started with the app when cases are configured) deletes every closed case whose date has passed and that isn't marked kept, the same way `DELETE /v1/cases/{id}` does: its documents with their index and files (`documents.delete_all` in the case's scope), its conversations, its access log and the case itself, with one log line per case (its id only). What deletion guarantees on the appliance (the files in the work directory, backups, the sandbox) is suveryn-tracker#31's; until then it is what deleting a document guarantees today. A case closed before a period is chosen keeps `keep_until` null: choosing a period later doesn't date it; its manager closes and reopens it, or the office deletes it by hand.

**Shared conversations and the administrator's pages** (stage 4, decision 12). A conversation in a case is its starter's until they share it with the case (`POST /v1/conversations/{id}/share`): then everyone who may read the case sees it in the case's list and can open it, read-only (only its owner saves, unshares or deletes it; nobody continues someone else's conversation). Sharing needs an open case and the contributor's right, and is noted in the access log. Deleting a case's document cleans every member's conversations that cite it, not only the deleter's, since the document was the case's. An administrator lists every case with who manages it (`GET /v1/admin/cases`, nothing from inside a case) and hands cases over from there (decision 6), and changes the office's two case settings in the dashboard (`PUT /v1/admin/cases/settings`): the environment (`SUVERYN_CASES_DEFAULT_ACCESS`, `SUVERYN_CASES_KEEP`) gives the values the appliance was provisioned with, the `case_settings` table what an administrator chose since, and every request sees the merged result (`CaseSettings.with_overrides`); a bad row is ignored rather than locking the office out.

**Administrators** have the Keycloak realm role `suveryn-admin` (see [keycloak/README.md](keycloak/README.md)). The gateway reads realm roles from the access token, where Keycloak puts them, and again at every token refresh, so granting or revoking the role takes effect within one access-token lifetime. `/auth/me` returns `admin: true` for them. With sign-in off (loopback development only) the local user is an administrator.

Documents are private to the user who uploaded them: every document endpoint, upload job and grounded chat sees only the caller's own, and another user's document gets 404, like a missing one (`owner_of` in `routes/common.py`).

Every `/v1/...` endpoint needs a signed-in user: 401 without one, 503 if sign-in isn't configured or Keycloak can't be reached.

## Sign-in

[`auth.py`](src/suveryn_api_gateway/auth.py) connects the gateway to Keycloak over OpenID Connect. Keycloak itself is a separate service: installed by [suveryn-appliance](https://github.com/suveryn/suveryn-appliance) on an appliance, and run locally for development as described in [keycloak/README.md](keycloak/README.md).

- **Backend-for-frontend.** The gateway is a confidential client and runs the authorization-code flow with PKCE (S256) itself. Tokens stay in the gateway's memory. The browser gets only an opaque session cookie: HttpOnly, SameSite=Lax, and `Secure` with a `__Host-` name when `SUVERYN_PUBLIC_URL` is https. JavaScript in the UI never sees a token.
- **Login safety.** A sign-in in progress (`state`, `nonce`, PKCE verifier, return path) travels in a short-lived HttpOnly cookie, encrypted with AES-GCM under a key derived from the client secret: it is bound to the browser that started it (no login CSRF), can be used once, and the server keeps nothing for sign-ins that are never finished, so a flood of `/auth/login` can't push out a real user's. A `nonce` ties the ID token to the login; after login the gateway redirects only to a path on its own site (no open redirect).
- **Rate limits** ([`ratelimit.py`](src/suveryn_api_gateway/ratelimit.py)): sign-in 30 per minute per client address, questions 20 and uploads 30 per minute per user; over the limit the answer is 429 with `Retry-After`. Set with `SUVERYN_RATE_SIGN_IN`, `SUVERYN_RATE_CHAT` and `SUVERYN_RATE_UPLOADS` (`0` turns one off). Behind a reverse proxy on another machine every request seems to come from the proxy, so raise the sign-in limit there or leave it to the proxy.
- **Token validation.** Signature against Keycloak's published keys (RS256 only; `none` and HMAC are refused), issuer, expiry (30 s leeway), audience for ID tokens, and authorised party for access tokens.
- **Sessions.** Access tokens are refreshed shortly before they expire. If Keycloak refuses the refresh (user disabled, session ended by an admin), the session ends: revocation takes effect within one access-token lifetime (5 minutes in the dev realm). Sessions live in memory, so a gateway restart signs everyone out; for the same reason the gateway runs as one process (`suveryn-gateway` refuses `WEB_CONCURRENCY` above 1; don't start it with uvicorn's `--workers` either), one gateway per appliance.
- **Cross-site requests.** `POST`/`PUT`/`PATCH`/`DELETE` with a session cookie must carry the UI's own `Origin`; otherwise 403.
- **API clients** may send `Authorization: Bearer <access token>` instead of a cookie; the same validation applies.
- **Identity methods** are Keycloak's choice: local accounts, optionally LDAP/AD federation and TOTP. **No social or online identity providers**, by design.

|---|---|
| `SUVERYN_OIDC_ISSUER` | Keycloak realm URL, e.g. `http://localhost:8180/realms/suveryn` |
| `SUVERYN_OIDC_CLIENT_ID` | Default `suveryn-chat` |
| `SUVERYN_OIDC_CLIENT_SECRET` | The client's secret (keep it in a `0600` file) |

Key points for reviewers:

- **Where things are.** [`app.py`](src/suveryn_api_gateway/app.py) builds the app: its lifespan (the model client, the document service, the stores, the hourly case sweep), the sign-in middleware with the rate limits, and the upload-size limit. The routes are one module per area in [`routes/`](src/suveryn_api_gateway/routes) (`signin`, `health`, `cases`, `playbooks`, `chat`, `documents`, `conversations`, `usage`); they read what they need from `app.state` and share the caller, the scope and the store checks through [`routes/common.py`](src/suveryn_api_gateway/routes/common.py). The stores and the rules are in the modules named above (`auth.py`, `cases.py`, `playbooks.py`, `conversations.py`, `usage.py`, `directory.py`, `ratelimit.py`); the playbooks' content and identity are the `suveryn-playbooks` package.
- **Binding.** The gateway binds to `127.0.0.1` unless `SUVERYN_HOST` says otherwise. On a network it should sit behind the appliance's TLS reverse proxy, with an https `SUVERYN_PUBLIC_URL`; the gateway warns when it binds to a network address with an http public URL.
- **`/docs` and `/redoc` are off** unless `SUVERYN_API_DOCS=1`, because FastAPI loads them from public CDNs. That breaks air-gapped installs and contacts third parties.
- **Request and answer text are not logged**; the access log has method, path and status only.
- **Uploads never touch `/tmp`.** Starlette writes an upload over 1 MB to a temporary file before our code sees it. The gateway points `tempfile` and `TMPDIR` at `<SUVERYN_WORK_DIR>/tmp/<pid>` (0700, removed on exit; folders of crashed processes are removed on start). `suveryn-gateway` does this before starting; the app does it again on start-up when documents are enabled, so bare `uvicorn suveryn_api_gateway.app:app` is safe too.
- **Settings:** `SUVERYN_HOST`, `SUVERYN_PORT` (default `127.0.0.1:8000`), `SUVERYN_WORK_DIR`, `SUVERYN_DATABASE_URL`, `SUVERYN_CASES_DEFAULT_ACCESS`, `SUVERYN_CASES_KEEP`, `SUVERYN_CONVERSATIONS_KEEP`, `SUVERYN_TIMEZONE`, `SUVERYN_API_DOCS`, and the harness's `SUVERYN_LLM_*` (see the [root README](../../README.md#run-locally)).
- **Tests** (`tests/test_api.py`, `test_documents.py`, `test_main.py`, `test_auth.py`) run against a fake llama-server, a fake document service and a fake Keycloak that signs real RS256 tokens and checks PKCE, through `httpx.MockTransport`. No GPU, database or Keycloak is needed. `keycloak/live_login_check.py` checks the same against a real Keycloak.
