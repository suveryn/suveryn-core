# harness

Everything between a question and the model, and between the model and the person: what the model is
given, how it is called, and how its answer is checked before anyone sees it. Storage, rights and
screens are not here; they are the gateway's and the UI's. **Start with
[docs/harness.md](../../docs/harness.md)**, which follows one question through these modules.

| Module | Contents |
|---|---|
| `service.py` | `ChatService`: `answer()` (whole answer) and `answer_stream()` (`Status` events for each pipeline step, `Sources`, `Delta` events, then one `Done`). The pipeline: passages, prompt, model, checks |
| `grounding.py` | The grounded prompt (`GROUNDED_INSTRUCTIONS`, the numbered excerpts, the reminders before the question) and citation-marker parsing |
| `guard.py` | Document text is data, never instructions: chat-template control tokens made inert (`neutralise`), text addressed to an AI detected (`instruction_like`, suveryn-tracker#21) |
| `calc.py` | Server-side arithmetic: replaces `[[calc: …]]` markers with exact results and checks their figures against the passages, by value through `values` |
| `language.py`, `lang/` | The words of each language the harness reads in documents, one file per language ([lang/README.md](src/suveryn_harness/lang/README.md)); the number words and months are generated by [`tools/`](tools/README.md), the rest is by hand. No module holds a word of a language |
| `values.py` | The one reader of amounts, numbers and dates (`read`, `decimal_style`, `figure_value`): in figures, with scale words, in words, in Dutch, French and English (the number words and month names come from `language.py`), with what each measures (currency, percentage, surface, time); what each form means is `tests/reading_cases.json`. Imports nothing of the harness (`tests/test_layers.py`) |
| `support.py` | Does the source say it: figures in no passage (`unverified_figures`), and each citation against its own passage, the figures, dates, years and names of the claim before a marker must be in the passage it cites (`citation_issues`, suveryn-tracker#11). By rule, without another model call |
| `marking.py` | What the source card marks per marker: the sentences of the cited passage the claim rests on, and the claim's facts in them in any form (`support_spans`, suveryn-tracker#25). The same sentences as `support.py`; a playbook fact's passages are marked with it too (`facts.marked`), and the browser only shows what it is sent. Held to `tests/marking_cases.json` |
| `history.py` | What the model reads of a conversation before a new question (`conversation_history`): the completed question-and-answer pairs the server stored, newest kept, within the request's limits (suveryn-tracker#251) |
| `thinking.py` | Thinking before answering (*Fast* or *Thorough*): `THINKING_TOKENS` on top of the answer's own, and `ThinkSplitter`, which takes the reasoning out of the answer text when a server leaves it there, so the answer that is read, checked and saved never holds it |
| `checks.py` | A playbook's check steps: the manifest's rule computed on the run's values, read by kind; holds, fails or open, never a block |
| `identifiers.py` | Numbers that carry their own check (national register number, enterprise number, IBAN): their check digits checked by arithmetic, for a fact with a `format` |
| `facts.py` | A playbook's facts: asks for the playbook's table (once more, stricter, when it isn't one) and reads each fact with its passages and the same checks (`read_playbook`, `read_facts`) |
| `terms.py` | Values worked out from another fact: a date written as a term ("binnen vier maanden na de ondertekening", "binnen tien werkdagen na …") from the date the playbook says it counts from (`counts_from`; board P01), working days on the pack's calendar; an amount written as a percentage from the amount it is a share of (`share_of`). In Dutch, French and English; nothing when it isn't certain |
| `llm.py` | `LlamaServerClient`, an async client for llama-server: health, whole answers, streaming, stopping (closing the stream closes the connection, so llama-server stops). Every message is sent `neutralise`d, with `cache_prompt` on: follow-ups reuse llama-server's cache, which holds document text. With `user=`, each call's token counts go to its `on_usage` hook |
| `schemas.py` | `ChatRequest`, `ChatResponse`, `Citation`, `SourceRef`, `Calculation`, `CitationIssue` and the stream events: the API's request and answer shapes, shared with `rag` and the gateway. A request has at most 200 messages of 100,000 characters, `max_tokens` up to 8192, the last message the user's |
| `usage.py` | `UsageRecord` (user, kind, model, prompt/completion tokens; never text) and the `UsageRecorder` hook: token usage is captured here, once, for every model call (suveryn-tracker#7); the gateway stores it |
| `audit.py` | Audit events (ids, pages and kinds; never text), such as passages that address an AI |
| `messages.py`, `messages.json` | The registry of codes and the one way to use one (`message`, `Problem`); standard library only, as the appliance's web setup loads it ([messages.md](../../docs/design/messages.md)) |
| `setup-limits.json` | The web setup's field lengths (the name, the email address, the password's minimum and maximum): the setup screen and the appliance's setup service use all four; the appliance's Keycloak realm takes the password's minimum (suveryn-tracker#163) |
| `released.py`, `messages-released.json` | The list of released codes and the command that adds to it ([names.md](../../docs/design/names.md), *Released*) |
| `config.py` | `LLMSettings` from `SUVERYN_LLM_BASE_URL`, `SUVERYN_LLM_DEFAULT_MODEL`, `SUVERYN_LLM_TIMEOUT_S` |
